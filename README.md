# first-api

A small CRUD API for managing a to-do list — create, read, update, and delete tasks. Built to understand the request → response loop from the server side: five endpoints, an in-memory list standing in for a database, tested via curl and Swagger UI.

## Overview

This is a Task API with the four CRUD operations mapped onto HTTP methods: `POST` creates, `GET` reads, `PUT` updates, `DELETE` removes. Data lives in a plain Python list in memory — there's no database yet, which means every restart resets it back to three example tasks. That's deliberate: this assignment is about the API layer, not persistence. (A follow-up assignment covers moving this same API onto SQLite.)

## Features

- `GET /` — describes the API (name, version, endpoints)
- `GET /health` — health check
- `GET /tasks` — list every task
- `GET /tasks/{id}` — get a single task, `404` if it doesn't exist
- `POST /tasks` — create a task, `400` if title is missing/empty, `201` on success
- `PUT /tasks/{id}` — update a task's title and/or done status, `404` if unknown, `400` if the body is empty or the title is blank
- `DELETE /tasks/{id}` — delete a task, `204` on success, `404` if unknown
- Interactive Swagger UI at `/docs`, auto-generated by FastAPI
- Every error response returns JSON: `{"error": "..."}`

## Tech Stack

- **Language:** Python 3.10+
- **Framework:** FastAPI
- **Server:** Uvicorn (ASGI)
- **Storage:** in-memory Python list (no database)

## Endpoints

| Method | Path | Description | Success | Errors |
|---|---|---|---|---|
| GET | `/` | API info | 200 | — |
| GET | `/health` | Health check | 200 | — |
| GET | `/tasks` | List all tasks | 200 | — |
| GET | `/tasks/{id}` | Get one task | 200 | 404 unknown id |
| POST | `/tasks` | Create a task | 201 | 400 missing/empty title |
| PUT | `/tasks/{id}` | Update a task | 200 | 404 unknown id, 400 empty body/title |
| DELETE | `/tasks/{id}` | Delete a task | 204 | 404 unknown id |

## Usage

Start the server:

```bash
uvicorn main:app --reload
```

Test with curl:

```bash
curl -i http://127.0.0.1:8000/
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/tasks
curl -i http://127.0.0.1:8000/tasks/1
curl -i -X POST http://127.0.0.1:8000/tasks -H "Content-Type: application/json" -d '{"title":"Buy milk"}'
curl -i -X PUT http://127.0.0.1:8000/tasks/1 -H "Content-Type: application/json" -d '{"done":true}'
curl -i -X DELETE http://127.0.0.1:8000/tasks/1
```

Or open `http://127.0.0.1:8000/docs` for Swagger UI and try the full CRUD cycle from the browser with "Try it out."

## The mortality experiment

Create a few tasks, restart the server, then `GET /tasks` — they're gone, back to the three seeded examples. That's not a bug: the list lives in the Python process's memory, and restarting the process throws that memory away. This is the exact limitation the next assignment (moving to SQLite) fixes.

## Challenges & Learnings

Getting the error shape right took more thought than the happy path. FastAPI's default validation error is `422` with a `{"detail": ...}` body — this spec wants `400` with `{"error": ...}`, including a missing-title `POST` and an empty `PUT` body. Rather than hand-checking every route, a global exception handler on `RequestValidationError` normalizes any malformed request body to the required shape in one place.
